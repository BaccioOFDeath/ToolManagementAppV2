Design Brief
Make this app feel like a well-designed early WinForms desktop tool, not a modern web app.
The UI should feel practical, dense, calm, and native. Prioritize clarity, speed, and structure over novelty. The app should look like serious desktop software built for getting work done.
Design principles:
Prefer native-looking controls and desktop interaction patterns.
Keep layouts compact and aligned.
Use strong labels and clear section titles.
Favor information density over oversized whitespace.
Put actions close to the data they affect.
Optimize for keyboard use and fast repeated workflows.
Show results and validation immediately near the relevant inputs.
Prefer simple, obvious workflows over clever UI.
Visual rules:
Minimal decoration.
No trendy web-app styling.
No oversized rounded cards.
No excessive shadows, gradients, or floating panels.
Use restrained color and let hierarchy come from layout and typography.
Keep typography plain, readable, and consistent.
Use one strong title, one subdued subtitle, then the working controls.
Layout rules:
Prefer forms, toolbars, split panes, tabs, lists, and data grids.
Prefer top-to-bottom or left-to-right task flow.
Align labels and inputs cleanly.
Keep spacing tight and consistent.
Avoid large empty areas unless they serve readability.
Design each screen around one primary job.
Component rules:
Prefer tables over cards for structured data.
Prefer modal dialogs only when a decision truly blocks progress.
Use tabs only when content is meaningfully grouped.
Keep buttons standard and obvious.
Keep primary, secondary, and destructive actions visually clear.
Avoid custom controls unless they solve a real usability problem.
Interaction rules:
Fast startup and responsive UI.
Obvious focus states.
Sensible tab order.
Inline validation where possible.
Minimize animation.
Avoid hidden actions and ambiguous icons.
Support power-user workflows, especially keyboard shortcuts and multi-select where useful.
Avoid:
Card-heavy dashboard layouts.
Huge padding and oversized controls.
Mobile-style spacing.
Excessive rounded corners.
Decorative side panels with little function.
Generic component-library aesthetics.
“Clean” layouts that hide useful information.
Forcing desktop tasks into web-style interaction patterns.
Success criteria:
A user should understand the screen quickly.
Common actions should require minimal clicks.
Important data should be visible without drilling through layers.
The UI should feel stable, direct, and tool-like.
The app should look intentional rather than template-generated.
